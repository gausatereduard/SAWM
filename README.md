# Lab 3 — Guestbook (XSS Prevention)

## 1. What was added

- `guestbook.php` — guestbook form + list of all stored messages
- `helper/guest.db.helper.php` — SQLite connection + schema for the **guest** database
- `repository/guest.repo.php` — `createGuestMessage()` / `getAllGuestMessages()` (prepared statements)
- `guest.sqlite` — the **guest** database (auto-created on the first request)

Schema (database `guest`, single table `guest`):

```sql
CREATE TABLE guest (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    "user"            TEXT NOT NULL,
    text_message      TEXT NOT NULL,
    e_mail            TEXT NOT NULL,
    data_time_message DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

The form reuses the existing bare input markup from `secure/signup.php`, and `index.php` links to the guestbook.

## 2. How XSS is prevented

1. **Output escaping (main defense):** every value coming from the database or from the previous request is printed through `htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')`. This also covers values placed inside HTML attributes.
2. **Store raw, escape on output:** messages are saved unchanged in SQLite, so the data stays correct for other consumers; escaping happens in the HTML context only.
3. **Input validation (defense in depth):** required fields, max lengths (name 50, message 1000), and `filter_var(..., FILTER_VALIDATE_EMAIL)` for the e-mail.
4. **Prepared statements:** the `INSERT` uses bound parameters, so the guestbook is not SQL-injectable either.
5. **Server-side timestamp:** `data_time_message` is generated by PHP, never taken from the request.
6. **POST → redirect → GET:** a successful post redirects to `guestbook.php`, preventing duplicate inserts on refresh.
